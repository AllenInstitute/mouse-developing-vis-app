Rebuilding and Deploying the Developing Mouse Visual Cortex Gene Expression Viewer

This guide documents the complete, reproducible workflow used to convert the public Developing Mouse Visual Cortex files from ABC Atlas Access into the pseudobulk and gene-level files required by the web application, publish those files to public AWS storage, run the R Shiny application, deploy it to Posit Connect, and configure GitHub to update the deployed application automatically.

Scope: This documentation applies only to the mouse-developing-vis-app repository and Developing Mouse Visual Cortex viewer. It does not document the SEA-AD Multiregion application.

Source repository: AllenInstitute/mouse-developing-vis-app
Live application: Developing Mouse Visual Cortex Gene Expression Viewer
Data documentation: ABC Atlas Access: Developing Mouse Visual Cortex

End-to-end workflow

  1. Create a GitHub repository and clone it into a linked Code Ocean Capsule.
  2. Configure a Python + R Code Ocean environment with all compiled and interpreted dependencies.
  3. Run create_dev_mouse_vis_cortex_pseudobulk.py to produce a pseudobulk H5AD.
  4. Capture the H5AD as a Code Ocean Data Asset and mount it under /data.
  5. Run create_mouse_aging_parquet.py to create gene-level Parquet and supporting metadata, excluding the statistics table.
  6. Run create_statistics.py to create the final exploratory gene-statistics table.
  7. Run create_value_sets.py to create authoritative category order and color definitions.
  8. Upload the app-ready directory from /results to a public S3 prefix and verify parity.
  9. Test code/shiny/app.R against the public S3 files.
  10. Create and validate a reproducible renv.lock.
  11. Deploy the app to Posit Connect.
  12. Configure GitHub Actions to regenerate the deployment manifest from renv.lock and update the existing Connect content after changes under code/shiny/.
  13. Publish index.html and this deployment guide with GitHub Pages.

2Convert and Format Back-end Files

Run create_dev_mouse_vis_cortex_pseudobulk.py

code/create_dev_mouse_vis_cortex_pseudobulk.py

Downloads the public Developing Mouse Visual Cortex data through AbcProjectCache, reads the raw count matrix in backed mode, and aggregates cells in chunks. The output has one row per library_label × cluster_alias, one column per gene, summed raw counts in X, sparse detection counts in layers["number_of_cells_expressing"], library/donor/taxonomy metadata in obs, and number_of_cells for each pseudobulk observation.

For every chunk, the aggregation computes both group_matrix @ count_chunk and group_matrix @ (count_chunk > 0). The second result is stored as unsigned integer counts and is the numerator for fraction expressing.

Use this run script:

#!/usr/bin/env bash
set -euo pipefail

mkdir -p /data/abc_atlas_cache
mkdir -p /results

python /code/create_dev_mouse_vis_cortex_pseudobulk.py \
  --cache-dir /data/abc_atlas_cache \
  --output /results/Developing_Mouse_Visual_Cortex_library_cluster_pseudobulk.h5ad

Run:

bash /code/run

Validate:

python - <<'PY'
import anndata as ad
path = "/results/Developing_Mouse_Visual_Cortex_library_cluster_pseudobulk.h5ad"
adata = ad.read_h5ad(path, backed="r")
print(adata.shape)
print(adata.obs.columns.tolist())
assert "library_label" in adata.obs.columns
assert "cluster_alias" in adata.obs.columns
assert "number_of_cells" in adata.obs.columns
assert "number_of_cells_expressing" in adata.layers
assert adata.layers["number_of_cells_expressing"].shape == adata.shape
assert adata.obs["number_of_cells"].min() > 0
adata.file.close()
print("Pseudobulk structure validation succeeded")
PY

Validate that all detection counts are between zero and the total number of contributing cells:

python - <<'PY'
import anndata as ad
import numpy as np
from scipy import sparse

path = "/results/Developing_Mouse_Visual_Cortex_library_cluster_pseudobulk.h5ad"
adata = ad.read_h5ad(path, backed="r")
detected = sparse.coo_matrix(adata.layers["number_of_cells_expressing"])
number_of_cells = adata.obs["number_of_cells"].to_numpy()
assert np.all(detected.data >= 0)
assert np.all(detected.data <= number_of_cells[detected.row])
adata.file.close()
print("Detection-count validation passed")
PY

Run create_mouse_aging_parquet.py

code/create_mouse_aging_parquet.py

Reads the mounted pseudobulk H5AD and writes the app-ready gene-level Parquet resource plus metadata. Each gene file contains sample_id, summed_counts, and unsigned-integer number_of_cells_expressing. The script validates the detection layer against number_of_cells and performs a Parquet read-back check. It does not create the statistics table; statistics are deliberately generated in the next independent step.

Run:

python /code/create_mouse_aging_parquet.py \
  --input "/data/mouse_vis_cortex_pseudobulk/Developing_Mouse_Visual_Cortex_library_cluster_pseudobulk.h5ad" \
  --output-dir "/results/mouse_vis_cortex_parquet"

Expected output:

/results/mouse_vis_cortex_parquet/
├── counts_by_gene/
│   ├── gene=<gene_key>/
│   │   └── data.parquet
│   └── ...
├── metadata/
│   ├── obs_metadata.parquet
│   ├── gene_map.parquet
│   └── CPM_scaling.csv
└── manifest.json
  • Each gene directory currently contains one Parquet file, but the app reads the directory as a dataset so additional files are supported.
  • Every new gene file must contain sample_id, summed_counts, and number_of_cells_expressing.
  • obs_metadata.parquet contains the full pseudobulk metadata and unique sample_id.
  • gene_map.parquet maps user-facing gene symbols to filesystem-safe gene keys.
  • CPM_scaling.csv contains library_label and CPM_scaling_factor in the same row order as every gene file and metadata table.

Run create_statistics.py

code/create_statistics.py

Reads the pseudobulk H5AD and generates the final exploratory statistics table independently of the Parquet conversion. Keeping this separate permits statistics to be revised without regenerating thousands of gene files.

Run:

python /code/create_statistics.py

The script writes:

/results/mouse_gene_summary_statistics.csv

Move or copy the generated file into the app-ready directory:

mkdir -p /results/mouse_vis_cortex_parquet/statistics
cp /results/mouse_gene_summary_statistics.csv \
  /results/mouse_vis_cortex_parquet/statistics/mouse_gene_summary_statistics.csv

The current table retains expression summaries and replaces the former (>0) pseudobulk metrics with true cell-detection summaries:

gene_symbol
ln(mean_CPM+1)
age_log2fc
frac_expr
age_frac_diff
max_ROI
log2fc_ROI
max_frac_ROI
frac_diff_ROI
max_subclass
log2fc_subclass
max_frac_subclass
frac_diff_subclass
gene_type
  • age_log2fc compares mean CPM among the script-defined postnatal reference group with mean CPM among embryonic observations.
  • frac_expr is the overall weighted fraction expressing: summed expressing-cell counts divided by summed total-cell counts.
  • age_frac_diff is the postnatal-minus-embryonic percentage-point difference in fraction expressing.
  • max_frac_ROI and max_frac_subclass identify the ROI and subclass with the highest weighted fraction expressing.
  • frac_diff_ROI and frac_diff_subclass summarize the corresponding difference in fraction expressing.
  • gene_type supports exact category filtering in the statistics table.

Keep the six short names synchronized between create_statistics.py and table_column_definitions.csv so the table tooltips remain accurate.

4Build and Test the Shiny Application

Application files

code/shiny/app.R

The complete R Shiny application. It loads lightweight metadata and statistics at startup, lazily retrieves selected gene directories from public S3, calculates CPM, caches retrieved genes, supports stacked categorical and numeric filters, and provides trajectory, heatmap, dot, violin, and two-gene correlation plots. Plot views include exploratory Spearman, Moran's I, Kruskal-Wallis, or Pearson statistics as appropriate.

How the app reads the published data

The app uses an anonymous Arrow S3 filesystem:

s3_bucket_name <- "sea-ad-single-cell-profiling"
s3_region <- "us-west-2"
s3_prefix <- paste0(
  "Multiregion_2026/previous_objects/parquet/",
  "TEST_dev_mouse"
)
s3_anonymous <- TRUE

At startup the app reads:

  • metadata/obs_metadata.parquet
  • metadata/gene_map.parquet
  • metadata/CPM_scaling.csv
  • metadata/value_sets.csv
  • statistics/mouse_gene_summary_statistics.csv

For a selected gene, it opens the entire directory:

counts_by_gene/gene=<gene_key>/

This permits one or multiple Parquet files per gene while avoiding discovery of the complete gene collection. The reader joins by sample_id, calculates CPM = summed_counts × CPM_scaling_factor, validates detection counts against number_of_cells, and calculates fraction_expressing. Retrieved genes are cached in memory.

The app derives stage at startup: donor ages beginning with E are labeled embryonic, and ages beginning with P are labeled postnatal. This app-only metadata field is then available for filtering, faceting, axes, and colors.

Preserve compact URL bookmarks

The app uses URL bookmarking but excludes ordinary Shiny and DataTable inputs dynamically. Only the compact custom viewer_state is saved. This prevents oversized URLs such as those caused by gene_statistics_table_rows_all.

  • Keep observe({ setBookmarkExclude(names(input)) }, priority = 1000).
  • Save the primary gene, optional comparison gene, dynamic filter field-to-value mapping, metric, plot type, axes, facets, colors, limits, pagination, and display settings in state$values$viewer_state.
  • During restoration, retain saved dynamic-filter values until the browser-created filter inputs exist and report the expected selections.
  • Trigger plotting only after the gene data and all dynamic filters are ready.
  • Capture plot settings in a reactiveVal() before selecting the plot tab; do not rely on lazy eventReactive() evaluation.

Create .github/workflows/deploy-connect.yml

.github/workflows/deploy-connect.yml

Runs after changes under code/shiny/, restores the exact R environment from renv.lock, generates a fresh strict deployment manifest, verifies that no private Code Ocean repository URL is present, and updates the existing Connect content.

name: Deploy Mouse Aging App to Posit Connect

on:
  push:
    branches:
      - main
    paths:
      - "code/shiny/**"
      - ".github/workflows/deploy-connect.yml"
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: deploy-mouse-developing-vis-app
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-22.04

    env:
      RENV_PATHS_ROOT: ~/.cache/R/renv
      RENV_CONFIG_REPOS_OVERRIDE: https://cloud.r-project.org

    steps:
      - name: Check out repository
        uses: actions/checkout@v6

      - name: Set up R
        uses: r-lib/actions/setup-r@v2
        with:
          r-version: "4.3.3"
          use-public-rspm: true

      - name: Restore renv environment
        uses: r-lib/actions/setup-renv@v2
        with:
          working-directory: code/shiny
          cache-version: 2

      - name: Verify restored deployment environment
        shell: Rscript {0}
        run: |
          renv::load("code/shiny")
          stopifnot(requireNamespace("rsconnect", quietly = TRUE))
          cat("rsconnect:", as.character(packageVersion("rsconnect")), "\n")
          cat(paste(.libPaths(), collapse = "\n"), "\n")

      - name: Generate deployment manifest
        shell: Rscript {0}
        run: |
          renv::load("code/shiny")
          setwd("code/shiny")

          options(
            repos = c(
              CRAN = "https://cloud.r-project.org"
            )
          )

          Sys.setenv(
            RENV_CONFIG_REPOS_OVERRIDE =
              "https://cloud.r-project.org"
          )

          app_files <- c(
            "app.R",
            "abc_atlas_gene_url_function.R",
            "abc_atlas_schema_kiwi.txt",
            "table_column_definitions.csv",
            "renv.lock",
            list.files(
              "www",
              recursive = TRUE,
              full.names = TRUE
            )
          )

          rsconnect::writeManifest(
            appDir = ".",
            appFiles = app_files,
            appPrimaryDoc = "app.R",
            dependencyResolution = "strict",
            packageRepositoryResolutionR = "lax",
            verbose = TRUE
          )

          manifest_text <- paste(
            readLines("manifest.json", warn = FALSE),
            collapse = "\n"
          )

          stopifnot(
            !grepl(
              "codeocean.internal",
              manifest_text,
              fixed = TRUE
            )
          )

      - name: Verify deployment files
        shell: bash
        run: |
          test -f code/shiny/app.R
          test -f code/shiny/abc_atlas_gene_url_function.R
          test -f code/shiny/abc_atlas_schema_kiwi.txt
          test -f code/shiny/table_column_definitions.csv
          test -f code/shiny/renv.lock
          test -f code/shiny/manifest.json
          test -f code/shiny/www/allen_institute_logo.svg
          test -f code/shiny/www/Developing_Mouse_Visual_Cortex_logo.png
          test -f code/shiny/www/tokens.csv

      - name: Deploy to Posit Connect
        uses: posit-dev/connect-actions/deploy@main
        with:
          connect-server: https://molgen-shiny.org
          connect-api-key: ${{ secrets.CONNECT_API_KEY }}
          content-guid: 3906a801-fab5-41e4-9c78-d7ce47cc0065
          path: code/shiny
          draft: false

After committing the workflow, monitor the first run under the repository's Actions tab. The workflow can also be run manually because it includes workflow_dispatch.

Update R dependencies safely

  1. Make package changes in a clean local project environment.
  2. Run the application and complete functional tests.
  3. Run renv::snapshot() with the explicit package list, including rsconnect.
  4. Run renv::status() and verify critical installed and locked versions match.
  5. Commit renv.lock with the app change.
  6. Push to a branch and, if desired, test against a temporary Connect content item before merging to main.
Why rsconnect is locked: The GitHub workflow calls rsconnect::writeManifest() from the restored project library, so rsconnect and its recursive dependencies must be present in renv.lock even though the Shiny runtime does not call them.

When only app.R or CSS changes

  1. Test locally.
  2. Commit changes under code/shiny/.
  3. Push or merge to main.
  4. Confirm the GitHub Action succeeds.
  5. Validate the live app.

  1. Update the local project library.
  2. Test all application functionality.
  3. Run the explicit renv::snapshot().
  4. Commit both code and renv.lock.
  5. Review the Connect build log after deployment.

Commit and deploy future application updates

After editing and testing the application locally, review the changed files, commit them, and push the branch. Changes under code/shiny/ trigger the Posit Connect deployment workflow after they reach main; root documentation updates are published through the configured GitHub Pages source.

If only some files changed, include only those files in git add. Do not commit manifest.json, local renv libraries, generated scientific data, credentials, or ignored runtime artifacts.

After pushing, merge the tested branch to main using the repository's normal review process. Confirm the GitHub Actions deployment succeeds and validate the live app. For a direct update from main:

Before pushing: Run the local regression checklist, verify that table_column_definitions.csv accompanies app.R, and update renv.lock only when the tested package environment changed.

When source data or preprocessing changes

  1. Regenerate the pseudobulk H5AD if the aggregation definition changed.
  2. Capture the revised H5AD as a versioned Data Asset.
  3. Regenerate gene Parquet and metadata.
  4. Regenerate statistics independently.
  5. Regenerate value_sets.csv if taxonomy, anatomical labels, order, or colors changed.
  6. Validate all files and capture the complete output as a Data Asset.
  7. Upload to a new AWS test prefix.
  8. Test the app against the test prefix.
  9. Promote the tested prefix or update s3_prefix in app.R.
  10. Push the app change to trigger deployment.

Troubleshooting

SymptomLikely causeResolution
object 'counts_dataset' not foundThe global dataset was removed for faster startup but read_gene() still references it.Open the selected counts_by_gene/gene=<gene_key>/ directory inside read_gene(); do not open the full collection at startup.
First gene is as slow as startup used to beA delayed global dataset still discovers all gene partitions.Remove the delayed global dataset and open only the selected gene directory.
CXXABI_1.3.15 not foundArrow loads an older system libstdc++.Install current Conda C++ runtimes and place /opt/conda/lib first in LD_LIBRARY_PATH.
libssl.so.1.1 not found for R curlAn old R curl binary was compiled against OpenSSL 1.1.Install current libcurl/openssl and build the R curl package against that environment.
Incompatible methods ("Ops.S7_object", "+.gg")Incompatible ggplot2/S7 package stack.Use the validated ggplot2 3.5.2 environment.
Library and lockfile are out of syncThe active R library differs from renv.lock.Rebuild and test a clean library, then snapshot the tested package versions. Use strict resolution only after synchronization.
there is no package called 'rsconnect' in GitHub ActionsThe project library was restored but not activated in the standalone Rscript step, or rsconnect was omitted from the lockfile.Record rsconnect in renv.lock and call renv::load("code/shiny") before using it.
Connect cannot resolve codeocean.internalThe manifest captured Code Ocean's private package proxy.Set public repositories before manifest generation and fail the workflow if the private URL appears.
invalid 'width' or 'height' in plottingPlot output or parent containers report a transient invalid dimension.Use one explicit responsive sizing model, allow containers to shrink with min-height: 0, and avoid competing height calculations.
Windows shell script reports invalid pipefailCRLF line endings.Convert code/run to LF and enforce line endings with .gitattributes.
414 Request-URI Too LargeAutomatic bookmarking serialized DataTable and dynamic-input state, especially all table row indices.Dynamically exclude all ordinary inputs and store only the compact custom viewer_state.
Operation not allowed without an active reactive context during restorationA reactive value was read outside a reactive consumer.Wrap the read in isolate(), and keep dynamic filter restoration state until inputs confirm their values.
The first plot requires two clicksLazy eventReactive() evaluation races with plot-tab activation.Capture settings into a reactiveVal() first, then select the plot tab in session$onFlushed().
Plot continuously regenerates after resizingexecOnResize = TRUE reruns the complete expression while reactive height and scrollbar geometry change.Use execOnResize = FALSE; regenerate only after Generate plot or bookmark restoration.
LOESS warnings about singularities or failed groupsSome color/facet groups have too few distinct progression values for stable LOESS fitting.These warnings concern smoothing groups; use a linear fit or no fit for sparse configurations, and first ensure resize-triggered redraw loops are disabled.
Facet page errors such as missing TRUE/FALSE or argument length zeroThe dynamically created page input is briefly NULL.Default missing page size to 12 and missing or invalid page number to 1 before any if condition.
The ABC Atlas button keeps the first geneThe URL was calculated only for the first click or stored in a nonreactive browser handler.Regenerate a reactive URL whenever loaded_gene() changes and render the link from that value.
kiwi-schema cannot be foundNode cannot resolve the globally installed npm module.Install kiwi-schema with npm and set NODE_PATH=/opt/conda/lib/node_modules.
