Developing Mouse Visual Cortex Gene Expression Viewer

The Developing Mouse Visual Cortex Gene Expression Viewer is an interactive R Shiny application for exploring pseudobulk gene expression across developmental age, cell type, library, and anatomical metadata in the developing mouse visual cortex. Users can identify candidate genes from a sortable statistics table, retrieve one gene at a time from public AWS storage, filter the data, and generate trajectory, heatmap, dot, or violin plots.

The underlying resource is part of the Allen Brain Cell Atlas, an open-science platform for visualizing and analyzing multimodal single-cell data across the mammalian brain.

Launch the interactive viewer

Data

Scientific source

The viewer is based on the data resource associated with:

Gao, Y., van Velthoven, C. T. J., Lee, C., et al. Continuous cell-type diversification in mouse visual cortex development. Nature (2025). https://doi.org/10.1038/s41586-025-09644-1

The study presents a high-resolution transcriptomic and epigenomic cell-type atlas spanning embryonic through postnatal mouse visual cortex development. The version exposed through ABC Atlas Access contains 568,654 single cells and a four-level taxonomy with 15 classes, 40 subclasses, 148 clusters, and 714 subclusters.

Source documentation, notebooks, manifests, expression matrices, metadata, and taxonomy annotations are available through the Developing Mouse Visual Cortex dataset documentation and the ABC Atlas Access Python package.

Pseudobulk expression

The app is built from a pseudobulk AnnData (.h5ad) file generated from the raw Developing Mouse Visual Cortex single-cell count matrix. Raw counts were summed separately for each combination of library_label and cluster_alias. Consequently, each row represents one library-by-cluster pseudobulk observation, each column represents a gene, and each matrix value is the summed raw count for that gene across all contributing cells.

  • number_of_cells records the number of cells contributing to each pseudobulk observation.
  • Observation metadata retain the corresponding library, donor, developmental age, anatomical, and cell-taxonomy annotations.
  • Gene metadata and symbols are retained in the AnnData var table.
  • The large source files and intermediate ABC Atlas cache are not distributed through GitHub.

Gene-level Parquet files

The pseudobulk H5AD was converted into a gene-partitioned Parquet resource. Each gene is stored under counts_by_gene/gene=<gene_key>/, with a Parquet file containing sample_id and summed_counts. The app opens only the selected gene directory and supports one or multiple Parquet files within that directory. This avoids opening the complete gene-by-pseudobulk matrix during application startup or gene retrieval.

Expression is displayed as counts per million (CPM). A row-aligned CPM_scaling.csv file stores the scaling factor for each pseudobulk observation: 

CPM scaling factor = 1,000,000 / total counts across all genes in the pseudobulk observation
CPM for a selected gene = summed counts × CPM scaling factor

Users may display either CPM or ln(CPM + 1), and may optionally exclude zero-count observations.

Metadata and value sets

The app uses supporting files under the metadata directory:

  • obs_metadata.parquet contains pseudobulk observation metadata and the unique sample_id used to join gene counts.
  • gene_map.parquet maps gene symbols to source columns and filesystem-safe gene keys.
  • CPM_scaling.csv contains library_label and the row-aligned CPM scaling factor.
  • value_sets.csv supplies authoritative label order and color values for taxonomy, age, anatomy, and other categorical metadata fields.

The cell taxonomy includes class, subclass, cluster, and subcluster assignments. Plot, facet, legend, dropdown, and filtering order are drawn from value_sets.csv wherever a matching specification is available; values not represented in that file are retained rather than discarded.

AWS storage and access

Application-ready data are stored in a public Amazon S3 prefix. The app anonymously reads lightweight metadata and statistics at startup, then retrieves only the selected gene partition during interactive use. No AWS credentials are required to use or deploy the viewer.

The current test data reside at the public TEST_dev_mouse S3 prefix.


Using the viewer

Left control panel

The left panel controls gene retrieval, metadata filtering, expression scaling, and plot configuration.

Gene

  1. Enter or search for a gene symbol, or select a gene from the statistics table.
  2. Select Get gene data.
  3. The app opens the selected gene partition from S3, joins counts to pseudobulk metadata by sample_id, calculates CPM, and stores the result in an in-memory cache.

Once gene data have been loaded, changing filters or plot settings does not require another S3 request during the same session.

Filter and scale

  • Filter metadata selects a metadata field.
  • Include values restricts the plot to selected values from that field.
  • Discard observations with zero counts removes pseudobulk observations in which the selected gene has no counts.
  • Plot ln(CPM + 1) switches between log-transformed and untransformed CPM.

Plotting choices are recalculated after filtering, so high-cardinality fields may become available when the current subset contains a manageable number of values.

Plot controls

  • Plot type selects trajectory, heatmap, dot, or violin output.
  • Plot-specific controls select developmental age, axes, facets, color, trend line, and observation display.
  • Generate plot applies the current settings and opens the plotting tab.
  • Reset plot options restores the default settings.

Application tabs

Select gene of interest

This tab contains a searchable and sortable table of gene-level exploratory statistics. Numeric columns remain numeric for sorting and filtering and are displayed to three decimal places. The table is initially sorted in descending order by the first numeric expression column. Selecting a row places that gene into the Gene symbol control.

The table contains the following compact summaries:

  • ln(mean_CPM+1): natural log of the overall mean CPM plus one.
  • age_log2fc: log2 fold change comparing the mean CPM of postnatal observations at P40 or older with the mean CPM of all embryonic observations.
  • age_log2fc(>0): the same developmental comparison after excluding zero values within each group.
  • max_ROI: the region-of-interest label with the highest mean CPM.
  • log2fc_ROI: log2 fold change of the maximum ROI mean relative to the arithmetic mean of ROI-level means.
  • log2fc_ROI(>0): the analogous ROI statistic after excluding zero observations.
  • max_subclass: the subclass with the highest mean CPM.
  • log2fc_subclass: log2 fold change of the maximum subclass mean relative to the arithmetic mean of subclass-level means.
  • log2fc_subclass(>0): the analogous subclass statistic after excluding zero observations.
Important: These statistics are intended to direct exploration in the viewer. They are not a replacement for the statistical analyses reported in the source study.

Plot gene of interest

This tab displays the requested gene using one of four visualization types. The plot region resizes with the browser window, and faceted plots use matching y-axes to support comparisons.

Trajectory across development

The trajectory plot displays expression across developmental age. Age values are ordered biologically from embryonic to postnatal stages. Visual spacing between adjacent ages is capped at the equivalent of three days, preserving small developmental steps while compressing large unsampled intervals.

  • Progression axis defaults to developmental age.
  • Facet by separates eligible cell-type, anatomical, or other categorical groups.
  • Color by overlays an additional categorical field.
  • Trend line offers LOESS, linear fit, or no fitted line.
  • Show individual observations displays the underlying pseudobulk values.

Trajectory color fields are limited to at most 15 values and facet fields to at most 30 values in the currently filtered data.

Heatmap of mean expression

The heatmap displays mean expression for every observed combination of two selected metadata dimensions.

  • The default horizontal axis is donor_age.
  • The default second dimension is subclass.
  • Tile color represents mean expression.
  • Heatmap dimensions do not have a category-count restriction.

Dot plot of mean expression

The dot plot uses the same two-dimensional grouping as the heatmap.

  • The default horizontal axis is donor_age.
  • The default second dimension is subclass.
  • Both dot color and dot area represent mean expression.
  • A minimum plotted size equivalent to ln(CPM + 1) = 0.5 ensures that every observed combination remains visible.
  • Dot-plot dimensions do not have a category-count restriction.

Violin plot with observations

The violin plot shows the distribution of pseudobulk expression values across groups and facets.

  • The horizontal axis defines groups within each panel.
  • The second dimension defines facets.
  • Small transparent black points show individual pseudobulk observations.
  • The white point and error bar show the group mean and standard error.
  • Violin fills, axis levels, facets, and legend order use value_sets.csv.

Groups with fewer than two observations are omitted, and violin dimensions are limited to fields with at most 30 values after filtering.


Running the app

Most users should use the hosted Developing Mouse Visual Cortex Gene Expression Viewer. The repository also supports local development and reproducible deployment.

Requirements

  • R 4.3.3 or a compatible R installation;
  • S3 support in the arrow package;
  • shiny, bslib, arrow, dplyr, ggplot2, scales, shinycssloaders, cachem, and DT;
  • internet access to the public AWS data prefix.

The app uses renv.lock to record tested R package versions for local reproduction and automated Posit Connect deployment.

Local setup

  1. Clone the mouse-aging-app GitHub repository.
  2. Open RStudio in code/shiny/.
  3. Install renv if needed.
  4. Restore the tested dependencies from renv.lock.
install.packages("renv")
renv::restore()

Run the app

setwd("code/shiny")
shiny::runApp(".")

Alternatively, open app.R in RStudio and select Run App.
